# KAUPC2026 개인전 운영 모노레포 설계

## 목표

이 저장소를 KAUPC2026 개인전의 단일 운영 저장소로 전환한다. AWS 계정과 실제 참가자 계정은 만들지 않으며, 대회 설정·문제 패키지·참가자 화면·AWS 인프라 코드를 계정 발급 직전까지 재현 가능하게 준비한다.

## 범위와 제외 범위

포함:

- DOMjudge 기반 개인전 `KAUPC2026`의 대회 설정과 운영 절차
- 문제 `다리 추가하기`(내부 ID `addingbridges`)의 완전한 DOMjudge 문제 패키지
- Python 기준 정답, 독립 테스트 생성·검증, DOMjudge import 및 제출 검증
- 참가자/운영자 화면의 메뉴와 용어 정리
- AWS VM 배포를 위한 Terraform과 서버 초기화·백업 문서

제외:

- 실제 참가자·관리자 대회 계정 생성 및 배포
- AWS 계정, 실제 리전, 도메인, 키, AWS 자격 증명 저장
- DOMjudge 코어 소스 포크 또는 핵심 관리자 기능 삭제

## 구조

```
app/                 Docker Compose, DOMjudge 사용자화, 운영 설정
problems/
  addingbridges/     DOMjudge problem archive, Python reference solution, generators
infra/
  terraform/         AWS infrastructure as code
docs/                대회 운영·배포·복구 문서
scripts/             import, verification, backup helpers
```

기존 Compose와 사용자화 파일은 `app/`에 배치한다. 문제는 대회 UI에 직접 입력하지 않고 버전 관리되는 문제 패키지로 관리한다. 비밀값은 `.env`, `terraform.tfvars` 등 무시 대상 파일에만 저장하고, 저장소에는 안전한 `.example` 파일만 둔다.

## Phase 1: KAUPC2026 대회 골격

`KAUPC2026`를 개인 참가자별 순위가 계산되는 ICPC 방식 대회로 준비한다. 대회 시작, 종료, 순위표 고정 시각은 계정 발급 후 확정할 수 있도록 설정 파일의 명시적 변수로 분리한다. 참가자 계정은 생성하지 않으며, 계정 생성용 CSV 형식과 절차만 문서화한다.

사용 언어에는 최소 Python 3와 C++를 포함한다. Judgehost, DB, 영구 볼륨, 정상 상태 확인은 Compose 수준에서 유지한다. 운영 문서는 대회 전 점검, 시작, 진행 중 질의 처리, 종료, 결과 확정, 백업과 복구를 다룬다. 저장소의 `AGENTS.md`는 문제 추가·검증·배포 때 지켜야 하는 기계적 규칙만 포함하고, 사람이 읽는 운영 매뉴얼은 `docs/`에 둔다.

## Phase 2: `다리 추가하기` 문제

### 문제 정의

초기 무방향 양의 가중치 그래프에 대해 간선 추가와 두 정점 사이 최단 거리 질의를 처리한다. 제한은 `N <= 300`, `M <= 50,000`, `Q <= 50,000`, 추가 쿼리 수 `<= 500`, 간선 가중치 `<= 100,000`이다. 다중 간선과 단절 상태를 허용한다.

### 기준 정답

Python 3 기준 정답은 다음 알고리즘을 사용한다.

1. 초기 다중 간선을 최솟값으로 압축하고 Floyd-Warshall로 모든 쌍 최단 거리를 계산한다.
2. 새 간선 `(u, v, w)`가 들어오면 모든 `(i, j)`에 대해 새 간선을 한 번만 쓰는 두 경로를 후보로 계산해 거리를 갱신한다.
3. 거리 질의는 행렬에서 즉시 읽고, 도달할 수 없으면 `-1`을 출력한다.

각 추가는 `O(N^2)`, 질의는 `O(1)`이며, 총 작업량은 초기 `O(N^3)`과 최대 500회의 갱신으로 제한된다. Python에서 정수 오버플로는 없으며, 도달 불가값은 충분히 큰 정수로 표현한다.

### 패키지와 검증

DOMjudge problem archive에는 지문(Markdown/HTML), 예제 입출력, 제한, 문제 메타데이터, Python 기준 정답, 테스트 입력·정답 출력, 생성기와 검증기가 포함된다. 생성기는 다음 범주를 만든다.

- 간선이 없는 그래프와 단절 컴포넌트
- 동일한 두 정점의 여러 간선
- 새 간선이 최단 경로를 바꾸지 않는 경우와 크게 줄이는 경우
- 양 끝에서 이미 경로가 존재하거나 한쪽만 도달 가능한 경우
- 최대 정점 수 및 최대 추가 횟수

작은 무작위 입력은 독립적인 다익스트라 오라클로 모든 질의를 검산한다. 생성한 각 대형 입력은 기준 정답으로 출력 파일을 만들며, import 후 Python 제출이 정답 처리되는지 확인한다.

## Phase 3: 화면 정리

DOMjudge 원본을 수정하지 않는다. 기존 `custom/js`와 `custom/css`를 확장해 화면 표시만 바꾸므로 이미지 업데이트와 복구가 쉽다.

참가자 화면에서는 `문제`, `제출`, `제출 현황`, `질의응답`, `순위표`만 일상적인 동선으로 남긴다. 기본 문서, 대회 변경, 일반 DOMjudge 안내, 대회 운영에 필요 없는 메뉴 항목은 숨긴다. 기존 번역 사전에서 개인전에 어울리지 않는 “팀” 중심 표현은 “참가자”로 바꾼다.

운영자 화면에서는 대회, 문제, 제출, 질의응답, 순위표, 참가자, 언어 설정을 우선 노출한다. 드물게 쓰는 시스템·분석·가져오기 기능은 메뉴에서 감추되, 기능과 직접 URL은 보존한다. 문제 추가와 장애 대응에 필요한 관리자 기능은 숨기지 않는다.

## Phase 4: AWS Terraform 및 배포 준비

Terraform은 AWS 계정 없이 작성·검증 가능한 모듈로 구성한다.

- 네트워크: 단일 VPC, 공용 서브넷, 인터넷 게이트웨이, 필요한 라우팅
- 컴퓨팅: Docker 실행 가능한 EC2, 영구 EBS 볼륨, Elastic IP
- 접근: HTTP/HTTPS와 운영용 SSH 또는 SSM 중 선택 가능한 보안 그룹 규칙
- 권한: 최소 권한의 인스턴스 역할과 SSM 관리 역할
- 초기화: Docker/Compose 설치, 저장소 또는 배포 번들 배치, Compose 기동

AWS 계정 ID, 리전, 인스턴스 크기, 허용 IP 범위, 키 이름, 도메인, 인증서 관련 값은 Terraform 변수로 둔다. `terraform.tfvars.example`은 완전한 값의 모양만 보여 주며 실제 값은 포함하지 않는다. 계정 수령 뒤에는 `init`, `plan`, `apply` 전 단계의 검증과 적용 후 DOMjudge·judgehost·영구 볼륨·외부 접속 확인을 운영 문서에 따른다.

## 오류 처리와 복구

- 문제 import 실패: 패키지 검증 스크립트에서 중단하고 원인을 출력한다. 운영 DB를 직접 편집하지 않는다.
- 채점기 불능: healthcheck와 judgehost 상태를 점검하고, 문제 데이터와 DB 볼륨은 보존한다.
- 화면 사용자화 오류: 커스텀 JS/CSS 마운트만 되돌려 기본 DOMjudge 화면으로 즉시 복구한다.
- AWS 배포 실패: Terraform 상태를 보존하고 `plan`으로 차이를 확인한 뒤 재시도한다. 영구 데이터 볼륨은 인스턴스 교체와 분리해 보호한다.

## 완료 기준

1. 빈 로컬 환경에서 Compose로 DOMjudge와 judgehost를 기동할 수 있다.
2. KAUPC2026 개인전 설정이 존재하고, 계정을 추가하면 즉시 참가시킬 수 있다.
3. `다리 추가하기` 패키지가 import되고 Python 기준 정답이 모든 테스트를 통과한다.
4. 참가자 화면에서 불필요한 메뉴가 보이지 않고 개인전 용어가 일관된다.
5. Terraform 형식·검증을 통과하며, AWS 계정 값 없이도 계획 단계까지 준비되어 있다.
6. 운영자가 문서만으로 대회 준비·시작·종료·백업 절차를 수행할 수 있다.
