# KAUPC 2026 요구사항 체크리스트

이 문서는 KAUPC 2026 개인전 DOMjudge 저장소와 참가자 화면의 완료 기준이다. 기능을 추가하거나 화면을 바꿀 때 이 항목을 생략하지 않는다.

## 1. 대회·계정·실행 환경

- [x] 대회는 개인전으로 운영한다.
- [x] 실제 대회 이름은 `KAUPC2026`으로 표시한다.
- [x] 별도 검증 대회 `TEST`를 유지한다.
- [x] KAUPC2026과 TEST는 2026-10-15까지 열리는 동일한 대회 기간을 사용한다.
- [x] 참가자 계정 `a / a`를 만든다.
- [x] 관리자 계정 `koala`를 만든다.
- [x] DOMjudge, MariaDB, judgehost를 Docker Compose로 함께 실행한다.
- [x] judgehost가 DOMjudge REST API에 인증되어 제출을 실제 채점한다.
- [x] 기본 Demo 대회는 참가자에게 보이지 않게 한다.
- [x] 과거의 중복 KAUPC 대회는 남기지 않는다.

## 2. 문제의 단일 원본과 자동 등록

- [x] 문제 원본은 `problems/contests/<대표 대회>/<라벨>/` 한 곳에만 둔다.
- [x] 다리 추가하기 원본은 `problems/contests/KAUPC/G/`이다. KAUPC 라벨은 쉬운 문제부터 A~J 순서다.
- [x] 원본 폴더에는 지문 HTML, 문제 메타데이터, 공개·비공개 테스트, 정답 코드, 생성기, 테스트를 함께 둔다.
- [x] DOMjudge용 ZIP은 원본에서 생성되는 전달물이며 별도 원본으로 관리하지 않는다.
- [x] 생성 ZIP은 `build/problem.zip`이고 Git에 넣지 않는다.
- [x] ZIP 내부 경로는 DOMjudge가 인식하는 `/` 구분자를 사용한다.
- [x] TEST는 문제 파일을 복제하지 않고 `problems/contests/TEST/A/source.txt`로 KAUPC/G 원본을 참조한다.
- [x] `docker compose up -d`만으로 대회 생성, 문제 ZIP 생성, 테스트케이스 등록, 대회별 문제 연결이 자동 수행된다.
- [x] KAUPC2026과 TEST에는 모두 라벨 `A`, 이름 `다리 추가하기`가 표시된다.
- [x] 두 대회 모두 A번의 공개 1개·비공개 4개 테스트케이스를 사용한다.
- [x] 새 문제 시작점으로 `problems/templates/standard/` 템플릿을 제공한다.
- [x] 새 문제 템플릿에는 설정, 지문 구조, sample/secret 데이터 구조, 기준 정답 코드, 작성 순서가 포함된다.
- [x] 출제 규칙과 원본·DB 경계는 `AGENTS.md`와 `docs/problem-storage-and-import.md`에 기록한다.

## 3. 문제 지문

- [x] 지문은 순수한 기본 HTML 나열 대신 문제 컴포넌트용 구조를 사용한다.
- [x] 지문에는 대회·문제 라벨, 제목, 시간 제한, 메모리 제한을 상단에 표시한다.
- [x] 지문에는 문제, 입력, 출력, 제한, 예제 섹션을 분리한다.
- [x] 예제는 입력과 출력을 별도의 다운로드 링크가 아니라 같은 예제 카드 안에 나란히 표시한다.
- [x] 문제 목록의 제목을 누르면 다른 페이지로 이동하지 않고 현재 DOMjudge 화면 위 지문 모달을 연다.
- [x] 지문 모달은 배경 클릭·닫기 버튼·Esc로 닫을 수 있다.
- [x] 기존 DOMjudge의 `예제` ZIP 다운로드 버튼은 새 문제 목록에서 보이지 않는다.

## 4. 참가자 정보 구조와 화면 전환

- [x] 홈(`/contest`)은 `대회 응시하기` 로비다.
- [x] 로비 상단 문구는 `KAUPC 2026`과 `대회 응시하기`만 표시한다.
- [x] 로비에는 현재 선택하지 않은 참가 가능 대회 카드만 표시한다.
- [x] 대회 카드를 누르면 선택 쿠키만 바꾸는 데 그치지 않고, 해당 대회의 전용 홈으로 이동한다.
- [x] 전용 대회 홈에는 해당 대회 이름과 `문제 목록`, `제출`, `순위표` 진입점을 제공한다.
- [x] 문제 목록(`/contest/problems`) 상단에는 `문제 목록`, `제출`, `순위표`, `질의응답` 탭을 표시한다.
- [x] 탭의 `문제 목록`은 현재 선택된 대회의 문제 목록을 연다.
- [x] 탭의 `제출`은 문제를 선택할 수 있는 제출 화면을 연다.
- [x] 탭의 `순위표`는 현재 선택된 대회의 순위표를 연다.
- [x] 대회 문제 목록은 기본 DOMjudge 카드 대신 AtCoder식 표로 표시한다.
- [x] 표 열은 번호, 문제, 제한, 제출이다.
- [x] 문제명 클릭은 지문 모달을 열고, 제출 클릭은 해당 문제 제출로 이어진다.
- [x] 문제 목록에서 기본 통계 막대, 유형, 예제 다운로드 버튼은 숨긴다.
- [x] 화면 전반에서 참가자 식별 열·라벨의 `팀` 표기는 `이름`으로 표시한다.
- [x] 대회 내부 페이지에는 대회명을 반복 표시하지 않고 기능명만 표시한다.
- [x] 제출 상세의 라벨과 컴파일 결과 안내는 한국어로 표시한다.

## 5. 디자인·품질 기준

- [x] 참가자 화면은 DOMjudge 안에서 동작하며 별도 프론트엔드 서비스나 외부 페이지로 분리하지 않는다.
- [x] 디자인은 백준의 명확한 섹션·제한 표기와 AtCoder의 대회용 문제 표 구성을 참고한다.
- [x] 색상·여백·테두리·버튼은 KAUPC 참가자 화면에서 일관되게 사용한다.
- [x] 좁은 화면에서는 문제 표의 낮은 우선순위 열을 숨기고 예제 카드를 세로로 배치한다.
- [x] 모달과 탭에는 의미 있는 접근성 라벨을 둔다.
- [x] 문제 목록, 대회 홈, 순위표, 제출 화면을 실제 브라우저 크기별로 육안 검토한다.

## 6. 검증 완료 기준

- [x] A번 기준 정답·생성기·패키지·프론트엔드 구조 테스트 7개가 통과한다.
- [x] 빈 Docker 볼륨에서 `docker compose up -d`를 실행해 자동 등록이 동작함을 확인한다.
- [x] MariaDB와 domserver가 healthy 상태다.
- [x] judgehost가 실행 중이고 제출 대기열을 조회한다.
- [x] API에서 KAUPC2026·TEST 두 대회만 활성 대회로 확인한다.
- [x] API에서 두 대회 모두 `A · 다리 추가하기 · 테스트 5개`로 확인한다.
- [x] `a / a`로 TEST 문제 목록에서 A번이 보임을 확인한다.
- [x] `a / a`로 KAUPC2026 문제 목록에서 A번이 보임을 확인한다.
- [x] `a / a`로 A번 지문 모달과 예제 입력·출력 카드가 보임을 확인한다.
- [x] `a / a`로 KAUPC2026 A번 기준 정답을 제출해 `AC`를 확인한다.
- [ ] 대회 카드 → 전용 대회 홈 → 문제 목록·제출·순위표 이동을 브라우저에서 한 흐름으로 확인한다.

## 7. 저장소·배포 기준

- [x] 구현 커밋은 원격 `master` 브랜치에 푸시한다.
- [x] AWS 계정을 받은 뒤에도 같은 Compose 구성과 문제 원본으로 배포할 수 있다.
- [ ] AWS Terraform 구성, 도메인, TLS, 영구 백업, 운영 비밀값은 AWS 계정 정보가 확보된 뒤 별도 단계로 구현한다.
