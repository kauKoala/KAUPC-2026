적절한 상대 찾기

시간 제한
1초
메모리 제한
512 MB

문제

마하는 온라인 체스 사이트의 매칭 시스템을 개발하고 있다.

사이트에는 N명의 플레이어가 있고, i번 플레이어의 레이팅은 A[i]이다.

얼마 전 배포한 매칭 시스템은 사용자들에게 혹평을 받았다. 레이팅이 비슷한 상대와는 승부가 좀처럼 나지 않아 지루하고, 레이팅 차이가 큰 상대에게는 손도 못 써 보고 진다는 것이다.

고민 끝에 마하는 새 매칭 규칙을 만들었다. 레이팅 차이가 L 이상 R 이하인 두 플레이어만 매칭 가능하다는 규칙이다. 즉, 1 ≤ i < j ≤ N이고 L ≤ |A[i] − A[j]| ≤ R인 쌍 (i, j)만 매칭 가능하다.

그런데 이 규칙대로라면 매칭 가능한 쌍이 너무 적어서, 상대를 찾지 못하고 기다리기만 하는 플레이어가 생길 수도 있다. 마하는 새 규칙을 적용하기 전에 매칭 가능한 쌍이 몇 개인지 미리 세어 보려 한다.

새 매칭 규칙에서 매칭 가능한 플레이어 쌍의 개수를 구하여라.

입력

첫째 줄에 세 정수 N, L, R이 공백으로 구분되어 주어진다.

둘째 줄에 N개의 정수 A[1], A[2], …, A[N]이 공백으로 구분되어 주어진다.

출력

매칭 가능한 플레이어 쌍의 개수를 출력한다.

제한

  • 2 ≤ N ≤ 300,000
  • 0 ≤ L ≤ R ≤ 1,000,000,000
  • 0 ≤ A[i] ≤ 1,000,000,000

예제

예제 입력 1
5 2 4
1 5 3 8 4
예제 출력 1
6
예제 입력 2
4 0 0
7 7 7 2
예제 출력 2
3
