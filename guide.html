01

계정 받기

관리자용

출제만 할 사람에게는 Jury User 권한만 주면 됩니다 — 문제·채점 관리는 가능하지만 대회 설정은 건드릴 수 없습니다.

→

Admin → Users → Add new user

Roles에서 Jury User 체크, Team은 -- no team -- 로 둡니다. 발급된 아이디/비밀번호를 출제진에게 전달하세요.

02

문제 만들기

두 가지 방법이 있습니다. 대부분은 방법 A로 충분합니다.

방법 A권장
1

Jury → Problems → Add new problem

Name, Timelimit(초), Type(보통 pass-fail)을 입력하고 저장합니다.

2

Testcases → edit

입력 파일(.in)과 정답 파일(.ans)을 업로드합니다. 참가자에게 공개할 1~2개만 Sample로 체크하고 나머지는 secret으로 둡니다.

3

Attachments → Add

문제 지문 PDF를 업로드합니다. 시간·메모리 제한은 지문에도 사람이 직접 적어야 합니다.

4

스페셜 저지가 필요하면

정답이 여러 개거나 오차 허용이 필요하면 Compare script를 커스텀으로 지정 — 이 경우 방법 B를 참고하세요.

방법 B고급 · zip 패키지

로컬에서 폴더를 만들고 zip으로 압축해 Import problem 에 올립니다. checker를 직접 작성해야 하는 경우에 씁니다.

문제이름/ ├── problem.yaml # name, timelimit ├── domjudge-problem.ini # 선택: 외부ID, 색상 ├── problem_statement/ │ └── problem.en.tex # 또는 .pdf ├── data/ │ ├── sample/ │ │ ├── 1.in │ │ └── 1.ans │ └── secret/ │ ├── 1.in / 1.ans │ └── 2.in / 2.ans └── output_validators/ # 스페셜 저지일 때만 └── checker.cpp
name: 'Hello World'
timelimit: 1

Demo contest의 hello / fltcmp / boolfind 를 Export해서 실제 구조를 참고하세요. fltcmp는 실수 오차 허용, boolfind는 인터랙티브 채점 예제입니다.

03

업로드 후 확인

필수

채점 파이프라인이 실제로 동작하는지 반드시 확인하고 넘어가세요.

체크기대 결과
정답 코드 제출Correct
오답 코드 제출Wrong Answer
무한 루프 코드 제출Time Limit Exceeded
참고 — judgehost 컨테이너가 멈춰 있으면 채점이 멈춥니다. docker compose ps 로 judgehost가 Up 상태인지 먼저 확인하세요.
04

대회 세팅

관리자용

지금 있는 demo 대회를 이름만 바꿔 재사용하거나 새로 만듭니다.

→

Jury → Contests → Add contest

Name/Shortname, 시작 시각, 진행 시간(4~5시간)을 입력합니다.

→

Problems 탭

문제를 순서대로 연결하고 문제 번호(A/B/C…)과 balloon 색상을 지정합니다.

→

Freeze time

순위표 프리즈 시각 — 보통 종료 1시간 전으로 설정합니다.

주의 — 대회 시작 후 테스트케이스를 바꿔도 이미 채점된 제출에는 소급 반영되지 않습니다. 반드시 시작 전에 03번(업로드 후 확인)까지 끝내 두세요.
